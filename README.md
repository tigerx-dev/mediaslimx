# MediaSlim X

简体中文 | [English](README.en.md)

![MediaSlim X · 图片、MP4 与 PDF 批量压缩工具](assets/brand/social-cover.png)

免费开源的本地批量压缩优化工具，面向网站图片、普通 MP4 视频与非加密的普通 PDF。图片支持 JPG、PNG 和静态 WebP；视频和 PDF 仅处理符合支持条件的文件，不承诺固定压缩比例。一套 Python 核心与中英文工作台，Windows 使用独立窗口，Linux/服务器继续使用网页，MIT 许可证。
**当前仅公开源码。** 可按下文在 Windows 或 Linux/WSL 安装依赖后运行；GitHub 仓库源码 ZIP 不是双击即用的 Windows 便携包。Windows 便携包与其他二进制下载仍待许可材料和干净 Windows 验收，本次不提供 Release 下载。
支持目录扫描、批量优化、三种输出、图片/视频预览、任务历史及恢复。PDF 支持导出或备份覆盖，不提供无备份覆盖。默认仅监听 127.0.0.1，不发送媒体到第三方，无遥测、账号和外部 CDN。目录扫描直接读取运行设备文件；拖拽导入会把所选文件副本传给当前服务。

## Windows：便携独立窗口（本地候选）
Windows x64 窗口版已接入现有工作台与 Python 核心，便携构建包含 Python、图片/PDF 引擎和 FFmpeg/ffprobe。完整解压窗口包后双击 `MediaSlimX.exe`，在工具自己的窗口使用，不启动外部浏览器。窗口依赖已安装的 **Microsoft WebView2 Evergreen Runtime**；不捆绑完整 Runtime，缺少时提示人工安装，不自动下载，也不静默改为浏览器模式。详见 [Windows 独立窗口](docs/windows-window.md)。

当前产物仅供本机验证，尚未发布下载。最新窗口候选采用官方 Python 3.13.16 与自建精简 FFmpeg/ffprobe，已通过本机实际解压 EXE 的合成媒体流程。lxml 静态 iconv 的精确构建来源和 LGPL 重链接材料仍待核实，干净 Windows 验收也未完成。验收主机已启用 Sandbox，Windows 要求手动重启后生效；Sandbox 仅用于开发验收，用户运行便携包不需要它。构建清单保留发行阻塞，不能把候选包称为正式发行版。构建、体积、数据位置与退出说明见 [便携包说明](docs/packaging.md)。源码启动方式如下。

窗口便携包自带媒体运行环境：不在首次启动时安装 Python、执行 pip 或下载媒体引擎；离线启动的前提包括 WebView2 Runtime 已安装。旧原型约 197 MiB，主要来自通用 FFmpeg；**最新独立窗口验证候选为 36.36 MiB ZIP**，还不是公开下载。第三方对应源码单独打包，普通运行不需要解压源码材料。

## Windows 源码：双击启动
日常在资源管理器中双击项目根目录的 **Start-MediaSlimX.vbs**，它会隐藏源码准备阶段的 PowerShell 终端并打开独立窗口；若启动准备失败，会提示改用 **Start-MediaSlimX.cmd** 查看详细错误。`.cmd` 是保留的诊断入口，会显示控制台。固定快捷方式时指向 `.vbs`，不要固定只负责显示的 `MediaSlimX.Window.exe`。
- 脚本按自身位置寻找项目，支持中文、空格以及从其他工作目录启动。
- 只使用 .venv-win，首次缺失时创建并安装 requirements-lock.txt；首次准备窗口组件还可能联网取得锁定的 WebView2 SDK，并使用 Windows .NET Framework C# 编译器构建助手。SDK 不等于 Runtime。
- 需要已安装的 Windows Python 3.10+；可用 py/Python PATH 或 MEDIASLIMX_PYTHON 指定完整解释器路径。不会把 WSL Python 当作 Windows Python。
- 默认在 8767–8866 中选择可用回环端口，通过 Windows `pythonw.exe` 打开独立窗口；任务数据为 `.mediaslimx/windows-window`。再次双击只尝试激活经校验的已有窗口，不接管其他网页服务。
- 独立窗口仅在网页工作台实际初始化等待时显示石墨／薄荷居中启动封面与真实版本号；就绪即进入，短活动线及底部淡薄荷光影不表示完成比例，不强制停留。启动失败可在同一画面查看原因并重试或退出；启动前服务失败保留 Windows 重试/取消提示。便携包自带 Python 与媒体库，封面不代表正在联网安装，也尚未检查更新。源码启动器会在窗口组件源码变化后的下次全新启动时重建它，已运行窗口仍可直接激活。说明和实际截图见 [Windows 启动状态](docs/startup-window.md)。既有便携候选尚未包含这次改动。
- 空闲关闭直接退出；任务繁忙时显示与当前主题、语言一致的退出层，默认聚焦“继续处理”，Escape、叉号和继续均保留工作。选择“保留进度并退出”会停止剩余处理，等待自己的事务、服务与助手安全收尾；已完成结果、未完成清单与备份保留。下次启动不会自动写入，须主动点击“继续剩余文件”。窗口页脚“退出工具”走同一流程；网页/服务器不显示该入口。当前源码与 r10 及更新的本机候选包含该流程，旧 r7 便携包不含。
- 选择其他端口：`Start-MediaSlimX.cmd -Port 8768`，安静入口的快捷方式可加 `-Port 8768`；指定旧数据目录可加 `-DataDir "完整 Windows 路径"`，切换目录不会自动搬移旧任务。保留的网页入口为 **Start-MediaSlimX-Browser.cmd**，仍默认 8766 / `.mediaslimx/windows`，可用 `-NoBrowser`；该入口保留终端，按 Ctrl+C 停止，关闭网页不会停止服务。
- **不要直接双击 `mediaslimx/static/index.html`。** `file://` 页面无法加载服务提供的 `/static/` 样式、脚本和受令牌保护的接口；Windows 网页版请双击 `Start-MediaSlimX-Browser.cmd`，通过启动时给出的完整 `http://127.0.0.1:端口/#token=...` 地址访问。网页版与独立窗口共用界面和处理核心，但任务数据目录分开。
- Windows FFmpeg/ffprobe 必须在 Windows PATH 中，WSL 里的 FFmpeg 不算 Windows 依赖。

## WSL / Linux
~~~bash
./start-wsl.sh
~~~
只使用项目 .venv，默认端口 8765；需要 Python 3.10+。缺失时创建虚拟环境并安装锁定依赖。
在浏览器打开终端给出的完整 URL；Linux 桌面可用 ./start-wsl.sh --open-browser。
首次运行也可以手动安装：
~~~bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m mediaslimx --allow-root /absolute/media/path
~~~
在 Linux 上用发行版包管理器安装 FFmpeg。
服务器通过 SSH 隧道访问，隧道本地端口应与服务端一致：
~~~bash
ssh -N -L 8765:127.0.0.1:8765 user@server
~~~
远程目录浏览器显示运行设备的目录，不会上传浏览器所在电脑的文件。

## 两个平台独立
| 项目 | Windows 独立窗口 | Windows 网页入口 | WSL / Linux |
| --- | --- | --- | --- |
| Python 环境 | .venv-win | .venv-win | .venv |
| 默认启动端口 | 8767–8866 中可用端口 | 8766 | 8765 |
| 默认任务数据 | .mediaslimx/windows-window | .mediaslimx/windows | .mediaslimx/wsl |
| 媒体路径 | D:\media | D:\media | /mnt/d/media |
| 视频依赖 | Windows FFmpeg/ffprobe | Windows FFmpeg/ffprobe | Linux FFmpeg/ffprobe |
Windows 与 WSL 不共用虚拟环境；Windows 两个源码入口共用 `.venv-win`，但窗口、网页与 WSL 的任务库、导入区和默认结果位置独立，预览 Cookie 按端口隔离。任务记录含绝对路径，不做跨平台自动映射。旧版 .mediaslimx/app 记录保持原位，可用对应平台显式 --data-dir 查看。
不要让多个实例同时覆盖同一批文件；数据隔离不会阻止其他进程写入相同媒体。

## 使用
1. 点击“选择目录”，在网页内浏览允许范围，不必手动拼路径；逐级浏览不会扫描，确认“扫描此目录”后直接检查候选媒体，仍需手动点击“开始优化”。手动粘贴路径或重查可用主界面的“扫描目录”。Windows 本地还有“系统选择并扫描…”按钮，可通过真实 Windows 文件夹窗口选择其他磁盘目录，选择后才加入允许范围并扫描。系统选择依赖 Windows Python 自带的 Tcl/Tk；缺少时会提示使用网页浏览或补装 Tcl/Tk。可以点击“取消系统选择”或关闭网页目录面板结束等待。
2. 也可粘贴绝对路径。源码双击入口授权本项目目录，服务器 CLI 默认启动目录；便携窗口默认从用户图片目录开始，没有该目录时从程序目录开始。CLI 可重复指定 --allow-root，Windows 系统选择也可主动授权其他目录。Windows 和 WSL 路径混用时会明确报错，不猜测转换。
3. 扫描真实 JPG、PNG、静态 WebP、满足条件的普通 MP4 和安装可选模块后的普通 PDF，查看跳过、损坏及不支持原因，可用“按类型选择”仅勾选 JPG（含 JPEG）、PNG、WebP、MP4 或 PDF，再手动调整；没有可处理文件的类型禁用，其他文件仍显示在列表中。
4. 选择画质优先、均衡或体积优先；默认仅压缩、保持原尺寸。可主动选择“压缩并等比缩小”，最大宽高是边界框，不裁切、不拉伸、不放大；未变小则保留原件和原尺寸。
5. 默认导出至新目录，原件留在原处；所选输出根目录下会建立带日期和短任务编号的独立目录（例如 `2026-10-18_15-30-00-a1b2c3d4`），避免不同任务互相覆盖。可主动勾选“备份原件，再原位优化”，指定备份目录后自动先复制原件、再把验证通过且更小的结果写回原路径。取消勾选回到导出；也可明确确认无备份直接覆盖。开始前查看目标预览；结果页默认缩显处理方式与结果位置，点击“目录详情”可看完整来源、结果及适用的备份目录与说明。Windows 独立窗口可在可用目录行点“打开”：结果行打开本次任务的导出目录或原位目录；服务器网页只展示运行设备路径。旧任务的完整编号目录保持原样。
6. 查看实际进度，取消剩余文件；检查逐文件结果、图片对比、视频播放、CSV 和历史。
7. 备份覆盖支持单文件及整批恢复。恢复冲突会跳过，保留当前文件及任务备份。
8. 最近任务第一行显示来源名称、第二行显示状态与上级路径；悬停可看完整路径。未固定任务悬停出现固定和单条归档操作，固定后图标常显。侧栏“整理”展开“归档未固定 / 已归档 N”，整批归档会先确认。固定项与进行中任务保留，已移出项可找回。目录快捷入口也可固定与归档；这些操作只整理显示，不删除媒体、导出、备份或任务数据，也不撤销允许范围。
异常后重启会核对原来进行中的任务，未完成项标为“已中断”，已完成项、导出与备份保留。当前源码与 r10 及更新的本机候选会在主区打开最近的中断或安全暂停任务，左侧“最近任务”也能找回；不会自动继续或写入媒体。用户主动点击“继续剩余文件”后，工具逐项复核原件、备份和目标，只处理未完成项；源变化或冲突会逐文件报错。左侧“媒体优化 ＋”用于新建任务，不清除旧记录。旧 r7 便携包仍是旧流程，没有续做入口。
界面按浏览器内容区自适应。建议 1280×720px 以上；宽屏下文件和参数独立滚动，开始按钮固定在参数区底部。矮窗口、窄屏或放大页面后可自然滚动，顶部应用栏保持可见，没有阻止使用的最小高度。
顶部 EN / 中文可切换语言并记住选择，保持当前待处理列表、勾选、设置和传输；主题按钮切换深浅主题。文件名、路径、媒体元信息、存储状态及 CSV 状态码不翻译，CSV 原因文本保留记录原文，系统诊断可保留原系统语言。目录浏览支持 Alt+O、Escape 与焦点返回，下拉支持方向键、Home/End、Enter/Escape。

输出和备份在根目录下按任务独立保存，保留文件名、相对路径和格式，不修改网站引用。无收益时原位保留，导出复制原件。
JPG/WebP/MP4 存在有损压缩，不承诺固定收益；PNG 优化编码，缩小尺寸会改变像素。直接覆盖没有原件，不提供虚假的前后对比或恢复。

参数栏标题旁可点“展开设置”放大同一份配置；开始按钮上方的“本次处理”可查看完整画质、尺寸、原件/结果/备份位置和恢复规则，查看不会创建任务。压缩结果保留原文件名、扩展名与相对目录，当前不提供批量重命名。

## 已验证与限制
- 最新 Windows 窗口本机候选为 `official-python313-r1`，ZIP 38,123,090B（36.36MiB）。实际解压 EXE 的隔离 WebView2 测试完成导入上限、201 文件目录扫描与导出、JPG/PNG/WebP/MP4/PDF 结果、CSV、预览、原件指纹、中英主题及空闲退出；PDF worker 四组通过。r10 的中断续做与窄窗边距证据仍按旧候选保留。新候选未完成繁忙物理标题栏 X 或真实干净 Windows 验收，不是公开发行版。详见 [窗口验证记录](docs/windows-window.md)。
- 历史r5实际主窗12项、目录对象9项、重开3项及显示故障收尾通过。用户协作确认空闲物理X关闭、繁忙X后选否继续；最后一次关闭时队列已完成，用户撤回曾点Yes的说法，不计为繁忙确认退出或剩余取消通过。Explorer手拖、目录人工点选、缺Runtime、普通账户与干净Windows仍未验。
- 历史Windows窗口r2便携候选已从真实ZIP解压运行，五类媒体导出、图片放大、视频、CSV、目录选择取消、重复启动、备份恢复与显示进程故障收尾通过；当时物理关窗确认未验。历史记录不转记到新候选，缺Runtime、普通账户与干净Windows仍待验，未上传发布。
- Windows 原生 Python 3.12、Windows FFmpeg/ffprobe 和 Windows Chrome 已验证；WSL2 Python 3.10、Linux FFmpeg 和 Chrome 独立验证。最新测试数量与本轮实际覆盖统一记录于 [平台状态](docs/platforms.md)，不把历史数量当作当前结果。
- 独立窗口源码已在本机真实启动，通过 WebView2 DOM 操作扫描两个合成媒体、默认导出并展示结果；1280×820 视口未见溢出或页面错误。关闭协调器和媒体安全退出经过两平台自动回归。各便携payload、人工协作与干净Windows按 [窗口记录](docs/windows-window.md) 分开确认；开发侧桌面点击工具因WSL工作目录URI初始化故障未能运行，不把DOM/协议测试写成人工点击通过。
- WSL 验证不等于独立 Linux 服务器或所有发行版验收；实体手机、Safari 和 macOS 尚未验证。手机功能与新增格式暂不扩展。
- 旧 Windows 网页启动器已从无关工作目录、中文带空格的独立项目路径启动并复用成功；新窗口入口的路径与二次激活按窗口记录单独验收。
- 两个平台均完成 320/390/768/1440px、深浅主题、44px 点击区域、焦点、减少动效、错误重试及过期响应检查。
- Windows 系统选择器单窗口显示、网页取消、关闭清理和重复启动已验证；实际点击系统文件夹并确认返回仍未自动验收。网页目录浏览器已真实操作验证。
- MP4 仅支持 H.264 8 位 SDR yuv420p + 至多一条 AAC 音轨；HDR、旋转、复杂流、动图等保守跳过。
- 图片不超过 5000 万像素，CMYK/高位深/EXIF 旋转保守跳过；只尽力保留常见元信息。
- 取消会停止本任务尚未提交的编码子进程，保留已完成结果；文件复制、指纹、原子替换及恢复等待安全边界。覆盖期间停止其他写入程序；特殊 ACL/扩展属性场景先用导出模式。
- 尚未开展 FIRANO 真实案例，不提供虚构收益。验证素材都是合成素材，不代表网站压缩效果。

## 拖入文件与整个文件夹
Windows独立窗口支持**拖入单个真实本机文件夹，直接扫描该目录**，默认准备导出并保留原件，不必因导入200项限制再重新选择目录。扫描只检查候选媒体，不自动压缩或覆盖；仍需勾选并点击开始。隐藏项、依赖、运行数据、输出与备份继续排除，默认 `mediaslimx-export` / `mediaslimx-backup` 等目录即使尚未登记也跳过。

此原生拖入能力只针对独立窗口的一次单文件夹拖入；空状态“选择本机目录”另通过受控系统目录选择器直接扫描。散文件、多个文件夹、普通浏览器/远程连接的“导入文件夹副本”，以及导入列表的“添加文件夹副本”仍按下面的副本导入规则处理、遵守200项/2GiB限制；浏览器按钮返回的FileList没有可靠目录对象，不从子文件猜测父目录路径。

其余副本导入流程中，把JPG/JPEG、PNG、静态WebP或普通MP4文件拖到页面，或点击“选择图片 / 视频”，完整传入并验证后加入待处理列表。可以继续添加；同一相对路径重名以 `名称 (2).扩展名` 区分，保留实际格式。文件夹副本导入保留最外层文件夹名及内部相对结构，例如“素材/images/a.jpg”出现在结果与ZIP中；不同目录同名文件独立保留，同一相对路径重名才编号。不复制空目录或非媒体文件。

文件只传给你正在连接的 MediaSlim X 服务：本机连接写入本机；通过 SSH 连接远程实例则传到该服务器，不发送第三方。浏览器不提供可靠的原文件绝对路径，因此**文件导入只允许导出**，不能覆盖、移动拖入的原件。处理完成可下载含结果媒体与相对路径 CSV 的 ZIP，也可查看服务端实际输出位置。

源码窗口把 Windows 导入副本写入 `.mediaslimx/windows-window/imports/`，默认结果为 `.mediaslimx/exports-windows-window/任务ID/`；保留的 Windows 网页入口分别为 `.mediaslimx/windows/imports/` 和 `.mediaslimx/exports-windows/任务ID/`。WSL 分别为 `.mediaslimx/wsl/imports/` 和 `.mediaslimx/exports-wsl/任务ID/`。便携窗口使用自己的 `%LOCALAPPDATA%\MediaSlimX\portable` 数据目录。导出位置可以修改，必须使用当前服务平台的绝对路径；不会猜测或转换 Windows/WSL 路径。

每个导入列表最多200个文件、2GiB，图片/视频单个最多1GiB、PDF单个最多64MiB。Windows独立窗口的“选择本机目录”直接打开系统目录选择器并扫描，不复制文件到导入区，也不触发浏览器的文件夹上传确认；扫描成功只准备默认导出的待处理列表，仍需点击开始。网页/远程连接的“导入文件夹副本”会把浏览器设备上的文件复制到当前服务，浏览器可能自行要求确认；“扫描运行设备目录”则在服务所在设备上找媒体，不传输副本。两者用途和路径范围不同。

空状态持续显示副本导入200项/2GiB提示，较大批量建议扫描运行设备上的目录。数量、目录项或层级超限时，面板列出已发现值与对应上限；批容量只说明2GiB上限，不提供精确已发现字节。面板说明本次新增传入为0，不截取前200项；已有列表、勾选、输出位置和模式保留。点击目录扫描入口后，只有扫描成功才切换来源并恢复默认导出；取消选择或扫描失败均保留旧导入。目录扫描成功也只准备待处理列表，仍需点击开始才优化。

当前实例导入区总声明容量上限8GiB，包括任务使用的原始副本。配额不足与单批超限分开提示，可进入“导入副本空间”查看占用并主动确认清理，不自动删除或释放副本。转为目录扫描后，旧导入副本也不自动丢弃；仍通过独立手动空间管理释放。传输过程中可以取消剩余部分，未完成文件不进入待处理列表。未使用导入仍可通过“清空导入”或“清理未使用副本”确认清理；历史副本受原有保护。

## 导入副本空间与安全清理
页脚“导入副本空间”显示当前实例的实际占用、声明大小预留配额、可用配额和逐批次状态。目录扫描不在这里复制媒体；Windows、WSL 和便携实例分别统计。

点击某批“释放副本”，先查看文件数量、预计释放大小、关联任务和未记录导出结果的副本数量，再主动勾选理解影响并确认。**此操作不可撤销，会失去导入原件预览；未处理、失败或未选择文件的副本也在清理范围内。** 请先在工具外保留需要的原件。

只删除本实例登记的导入副本，不删除拖入的原文件、导出、备份、任务、报告或处理指纹。保留的任务可继续导出 CSV、预览结果及下载结果 ZIP；不会虚构前后对比。删除任务记录后的历史副本也可在此单独释放，仍不会混入“未使用副本”快捷清理。

上传、处理、恢复或目录/文件校验异常时禁止清理；确认后数据变化会要求重新查看。部分清理失败时保留未完成文件和配额，重启不自动续删；用户重新查看、确认后重试。清理完成后释放该批配额，保留不含媒体字节的清理状态。详见 [空间管理说明](docs/storage-management.md)。

导入风险测试与浏览器验收：`tests/test_imports.py`、`tests/import-browser.cjs`。后者在隔离服务中运行，不修改正在使用的任务库，也不接触真实案例素材。

文件夹收集阶段即跳过点号隐藏项、依赖/构建/缓存目录、常见输出/备份名称及当前实例已登记的输出/备份目录名称，服务端再次校验；未被选中的项目代码和配置内容不读取、不传输。浏览器只提供相对名称，已登记目录采用名称保守排除。单批还限制 20 层目录、20000 个枚举项及 1024 UTF-8 字节相对路径；更大范围请走运行设备的目录扫描。浏览器不提供完整系统隐藏属性和链接元信息，严格按文件系统属性排除时使用目录扫描，详见隐私说明。

## 字号与原位优化入口
中英文共用 12px 最低字号：正文/输入 14px、控件 13px、辅助/表格/时间 12px，区块标题 16px，页面标题桌面 28px、手机 24px。后续界面按 DESIGN.md 维护，不通过缩小字号适配。

拖入仍是仅导出。若希望备份后更新原路径，可点击“选择原目录，备份后优化”：浏览运行设备上的目录，扫描成功后才替换导入列表并准备备份模式，仍需点击开始才写入；取消或失败保留原列表和设置。该主动备份入口与超限后的默认导出扫描分开。目录面板明确区分“扫描此目录”和“系统选择并扫描”，都只扫描，不自动压缩。运行设备若为服务器，应选择服务器上的路径，不猜测拖入原件的绝对位置；目录扫描也不绕过格式及PDF大小等媒体支持边界。


## 可选 PDF 优化
在需要PDF支持的平台单独安装，Windows与WSL不要混用虚拟环境：

~~~powershell
.venv-win\Scripts\python.exe -m pip install -r requirements-pdf.txt
~~~

~~~bash
.venv/bin/python -m pip install -r requirements-pdf.txt
~~~

重启该平台的服务后，可扫描或拖入普通 PDF。缺少依赖时逐文件显示安装提示，图片视频功能仍可用。PDF只做结构和普通/Flate流重压，不栅格化、不降采样图片、不改页面尺寸；画质和最大宽高不适用，不保证固定收益，已优化扫描件可能无收益。

默认导出保留原件；原位更新必须备份并验证较小结果，禁止无备份覆盖。加密/带权限限制、数字签名、表单、脚本/动作、注释（含链接注释）、附件、复杂流或损坏PDF明确跳过，不解密、不移除限制，也不自动修复。首版限制单个64MiB、1–1000页、50000对象、单流32MiB、总解码128MiB；独立子进程限制内存/超时。详情下载到本机阅读器检查，不在网页内嵌。

实现采用 [pikepdf保存API](https://pikepdf.readthedocs.io/en/latest/api/main.html)，验证页数、页面框/旋转、有序页面内容与嵌入流摘要；这些检查不等于逐页渲染或绝对语义等价验证。建议下载检查重要文档。

## 任务归档
鼠标移到单条已结束、未固定任务时，归档和固定图标会一起出现；键盘聚焦和触屏时也可操作。或从“整理”选择“归档未固定”并确认，把记录收进“已归档 N”。随时可恢复；固定与进行中任务保留。归档不删除任务/报告/导入原件副本/导出/备份，不释放这些文件占用，也不会30天后自动删除。目录快捷入口采用相同的可恢复归档语义，不改变访问范围。


## 彻底删除归档任务记录
归档列表可逐条“删除记录”，仅允许已结束、未固定且已归档的任务。先展示当前任务关联数量、报告/预览/恢复影响，主动勾选理解后才能确认；取消不改变任何记录，确认后无法从归档找回。固定、运行/恢复中、确认后记录状态变化或后台正在写任务时会拒绝。

此操作只删除任务数据库记录及其列表标记，不删除原文件、导出、备份、导入原始副本或以前保存的报告。删除后该任务的工具内CSV导出、预览、输出位置查询与自动备份恢复入口消失；有备份仍需自行定位并手动恢复，没有备份的任务不会因此获得恢复能力。请先保留需要的报告、输出与备份位置。

已用于任务的导入副本继续受持久保护，不会因删除记录而出现在“未使用副本”清理中。重复处理指纹仍保留，避免因清理记录再次有损压缩。只减少记录，不保证缩小SQLite物理文件，也不释放这些媒体文件占用。没有自动过期删除或批量清空文件。


## 文件详情
文件详情按结果摘要、前后预览、可读处理参数组织；原始JSON默认折叠在“技术详情”。无收益、重复跳过、已恢复分别说明真实采用情况，不把任务设置冒充实际编码。右上角叉号关闭，支持Escape与键盘焦点返回。
